### 架构决策
- 后端分层：`commands`（前端入口）→ `service`（采样/调度/响铃/托盘）→ `domain`（纯逻辑，可单测）→ `infra`（JSON 存储）+ `platform`（macOS/Windows/Linux 兼容层，只有 `InputMonitor` 与 `ShortcutWatcher` 两个 trait）。
- 存储走 JSON：`settings.json` / `alarms.json` / `activity/YYYY-MM.json`，月文件带内存缓存，写入用「临时文件 + rename」，失败退化为直接覆盖（macOS `com.apple.provenance` 会导致 rename EPERM）。
- 活跃状态机：1 分钟采样，冻结窗口内不断段，判定离开的时刻取"最后一次检测到输入"。
- macOS 用 `CGEventSourceCounterForEventType` 统计事件数（键鼠可分离、免辅助功能权限）；Windows `GetLastInputInfo`、Linux XScreenSaver（都无法分离键鼠，两字段同时置位）。
- 铃声不引音频库，直接调 `afplay` / PowerShell SoundPlayer / `paplay`。
- 响铃 = 声音 + 系统通知 + 独立置顶浮窗（`alarm.html`，Rust 按需创建/销毁）+ 80ms 轮询左右修饰键关闭。
- 每天进行中的时段每 5 分钟落一次检查点，避免异常退出丢数据（`coalesce` 会把重复写入合并成一段）。

## 修复：每次响铃弹「Where is use_default?」选择应用窗口

- 根因：`mac-notification-sys` 的 `send()` 在没设置过应用身份时会执行 AppleScript
  `get id of application "use_default"`（`ensure_application_set` → `get_bundle_identifier_or_default("use_default")`），
  LaunchServices 找不到这个"应用"就弹 Choose Application 对话框。
- 修法：`platform/notify.rs` 新增 `ensure_identity()`（`Once` 保护）+ 对外 `prepare()`，在 `lib.rs` setup 里调用一次
  `mac_notification_sys::set_application(...)`。之后 `INIT_APPLICATION_SET` 已完成，库不会再回头走 AppleScript。
- 身份选择：`current_exe()` 路径含 `.app/Contents/MacOS/` → 用 `tauri.conf.json` 的 identifier；
  否则（`tauri dev` 的裸二进制）→ `com.apple.Terminal`，与 `tauri-plugin-notification` 的 dev 分支一致。
  注意 `tauri::is_dev()` 不够用：debug 版 .app 里 is_dev=false 但同样是 bundle 运行。
- 验证（macOS 15.2）：dev 模式与 `bundle/macos/DiDaWork.app` 两条路径都跑了到点响铃，均无对话框；
  60s 后自动收尾正常，主界面横幅出现/消失正常；`cargo test` 16 项、`tsc --noEmit` 通过。
- 环境注意：这台机器当前不显示通知横幅（`osascript display notification` 也不显示），
  所以横幅本身只能靠 ncprefs 条目与通知回调日志佐证，不能靠截屏。
