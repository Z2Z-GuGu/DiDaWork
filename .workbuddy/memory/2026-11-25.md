## 铃声改成"一个文件夹一首音乐"的本地铃声库

需求：用 `doc/sound/` 里三首无版权音乐替代系统提示音，删除所有默认提示音；安装后内置三首放到用户
数据目录，用户自定义的也放同一目录；列表显示文件夹名 + 自定义添加按钮；文件夹里有版权 txt 时列表右侧
显示可点击的图标。

- **资源**：`doc/sound/{emotional-piano,love-story,medical}` → `src-tauri/resources/ringtones/`
  （每首一个 m4a + 一个 license txt）。`tauri.conf.json` 加 `"resources": ["resources/ringtones"]`，
  实际落在 `<App>.app/Contents/Resources/resources/ringtones`（保留了 `resources/` 前缀，
  `bundled_ringtones()` 里三个候选路径都试一遍；dev 兜底 `CARGO_MANIFEST_DIR/resources/ringtones`）。
- **domain/ringtone.rs**：`Ringtone { id, name, hasLicense }`、`is_audio`（只认 m4a/mp3）、
  `is_license`（txt）、`folder_name()`（清洗非法字符、去首尾点、48 字符上限）、`normalize()`（失效 id 回退第一首）。
- **infra/ringtones.rs**：`Library` 负责扫盘（每次实时扫，不建索引）、`seed()`（首次复制内置铃声，
  靠 `ringtones/.seeded` 标记只做一次，用户删掉的不再长回来）、`create()`（建目录 + 复制音频/txt，
  失败清理半成品目录）、路径穿越校验。单测 5 个。
- **platform/audio.rs** 重写：`play_file(Path, max_secs)` 循环播放；macOS `afplay`；
  Windows PowerShell + WPF `MediaPlayer`（SoundPlayer 只认 wav）；Linux 依次 ffplay/mpv/gst-play/cvlc。
  子进程活不到 500ms 就退出视为解码失败，跳出循环避免忙刷。
- **删除所有系统提示音**：macOS `/System/Library/Sounds`、Windows `Alarm0x.wav`、Linux freedesktop 音效全部移除。
- **迁移**：`AppState::new` 里 `migrate_ringtones()` 把老的 `glass`/`ping` 换成铃声库第一首（3 个单测）。
  注意顺序：lib.rs 必须**先 seed 再建 AppState**，否则首次启动时库是空的、迁移不生效。
- **命令**：`list_ringtones` / `preview_ringtone(id)` / `add_ringtone(name, audioPath, licensePath)`
  → `{ ringtones, created }` / `open_ringtone_license(id)`。
- **前端**：新增 `components/ui/popover.tsx`（radix popover，z-60 盖住 Dialog 的 z-50）、
  `features/alarms/RingtonePicker.tsx`（名字左对齐 + 版权图标右对齐 + 底部「添加自定义铃声」，
  展开时重新扫盘）、`features/alarms/AddRingtoneDialog.tsx`（音乐名必填 / m4a·mp3 必填 / txt 可选，
  用 `@tauri-apps/plugin-dialog` 选文件）。`AppDataProvider` 加 `refreshRingtones` / `addRingtone`。
- **依赖坑**：`npx tauri build` 会校验 npm 包与 cargo crate 的 major.minor 一致。
  `@tauri-apps/api` 被 `npm i` 顺手升到 2.12.5（crate 是 2.11.6）、plugin-dialog npm 2.8.4（crate 2.7.3）→ 构建直接报错。
  `cargo update -p tauri` 升不动（rust 1.85 限制），所以反向把 npm 包锁到 `@tauri-apps/api@2.11.1`、
  `@tauri-apps/plugin-dialog@2.7.3`（`--save-exact`），并把 `@tauri-apps/api` 的 `^` 去掉。
- **npm EIO 复现**：`node_modules/@tauri-apps/.api-xxxx` 残留目录会让 `npm install` 报
  `EIO: rename ... Directory not empty`，删掉残留目录即恢复。
- **capabilities**：新增 `dialog:allow-open`。绑定 m4a 播放用 `afplay -t 1` 实测通过。
- 测试：`cargo test` 29 项通过；`tsc --noEmit`、`vite build`、`tauri build --debug --bundles app` 均通过。

## 修复「下班后继续工作提醒」的两处逻辑漏洞

- 根因：`overtime_due` 只有下界（`now > clock_out`），没有上界，下午上班后仍会给上午组发"已经下班"；
  调度器也没有"这次加班已结束"的记忆，用户停手后再活跃会复活。
- 空间边界：`domain/alarm.rs` 新增 `active_on(alarm, date)` 与
  `overtime_window_end(alarm, all, date)`（取今天生效闹钟中 clock_in > 本组 clock_out 的最小值，缺省 24:00），
  `overtime_due(alarm, all, now, interval)` 改为要求 `now ∈ (out, end)`。
- 生命周期：`service/alarm_scheduler.rs` 的 `FiredLog` 升级为 `DayLog`，新增
  `overtime_active` / `overtime_ended` 两个集合，key = `id|clock_out 分钟数`（改下班时间自动重置）；
  下班后见到活跃→记"加班中"，随后见到空闲→`end_overtime`，当天不再触发。跨天 `roll()` 清空。
- 只在下班后"工作过又停下"才结束，避免刚启动就是空闲状态时误掐掉加班提醒。
- 测试：domain 侧 4 个新用例（窗口截止 14:00、12:10–13:50 共 11 次、停用/非当天闹钟不截断），
  scheduler 侧 4 个用例（结束、不误结束、跨天清空、改下班时间重置）。`cargo test` 36 项通过。
- 文案/文档：`settings.overtimeHint` 中英文改写；README 新增「加班提醒」小节（两条边界）；CHANGELOG 对应条目改写。
